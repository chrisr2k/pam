For Administrators

This section covers staff and admin duties. Everything here lives in the user menu (top right) or the Django admin at /pam-admin/.

Roles & approvers admin
  • Create and edit roles under Django admin → Roles → Privileged roles.
  • Assign approvers per role, and set the approval policy: Any one / All approvers / Fixed quorum (quorum is capped at the approver count so requests can never get stuck).
  • Anyone you add as a role approver can approve for that role — and becomes MFA-required automatically.
  • Roles with Requires approval off grant immediately on request.
  • Flag emergency roles as Break glass — they appear on the admin Break Glass page (no approval, MFA mandatory, all admins alerted).
Vault entries staff
  • Create entries under Vault (navbar). The secret is encrypted at rest and never displayed again.
  • Each entry auto-creates a role Vault: <name> — assign its approvers in the Django admin, not on the entry.
  • Manual rotation is available on the entry page; previously used values are rejected. Auto-rotate entries rotate whenever a checkout ends.
  • Rotation plugins sync the new credential to the real system: AWS IAM access keys (iam_user_name), Entra app client secrets (tenant_id, client_id; the app needs Application.ReadWrite.OwnedBy), SSH (host, username), PostgreSQL / MySQL (host, username; MySQL 8+), Windows WinRM (host, username; local admin or AD reset rights), and Generic HTTP (url + templates). Config holds connection info only — never secrets. Failed rotations keep the existing value and record a failed history entry.
  • Deleting an entry deactivates its role but keeps history; prefer deactivating while checkouts are active.
MFA administration
  • Users locked out of MFA (lost phone) can be reset: clear their otp_secret / mfa_enrolled_at in the Django admin user page, then they re-enroll at MFA Setup.
SIEM export staff
  • SIEM Settings: webhook URL (Splunk HEC / Sentinel / generic), payload mode, API token, optional action filter.
  • Events forward in order within ~45 seconds, at least once; failures surface as last error on the same page and retry automatically.
Notifications & reviews
  • Notification Settings: email (SMTP), Slack, Teams, with per-event toggles — including the break-glass alarm (default on, alerts all admins).
  • Reviews: create recertification campaigns, assign reviewers, track decisions.
Threat analytics staff
  • Alerts (navbar): every rule firing, with severity, details, and an Acknowledge button.
  • Threat Settings: enable/disable each rule and tune its thresholds — impossible travel (logins from multiple IP networks), off-hours elevation, MFA storms, checkout spikes, and vault reveal spikes.
  • The scan runs every 60 seconds. Each alert also lands in the audit log (and your SIEM) and can notify all admins by email/Slack/Teams. Duplicate alerts for the same subject are suppressed during the cooldown window.
  • Off-hours boundaries are evaluated in the server timezone (UTC).
Access review campaigns staff
  • New Review: creates a campaign from grant history — one entry per user/role pair that has ever held access (break-glass excluded). The optional unused access filter mines for entitlements whose most recent grant is older than N days.
  • Assigned reviewers decide each entry (Approve = keep / Revoke = remove) with a comment; per-entry usage stats show how much the access was actually used. When the last entry is decided, the review completes automatically.
SCIM / Entra user provisioning staff
  • SCIM Settings: enable the endpoint, copy the tenant URL (/scim/v2/) and generate a secret token (openssl rand -hex 32).
  • In Entra: Enterprise applications → new (non-gallery) → Provisioning → Automatic → Tenant URL + Secret Token → Test connection → set attribute mappings (userPrincipalName → userName, mail → email, accountEnabled → active) → leave group provisioning disabled.
  • Provisioning creates and updates users; deprovisioning deactivates the account (never deletes — audit history is preserved). PAM roles default to Requester; assign approver/admin roles in the Django admin.
Never rotate SECRET_KEY without exporting vault secrets first. It is the encryption key for every stored vault value and the signing key for configuration secrets — rotating it destroys them permanently.
