Option A: IAM Instance Profile Best for AWS

If PAM runs on EC2, ECS, or EKS, no credentials needed.

  1. Attach an IAM role to your compute resource
  2. Grant it sso:CreateAccountAssignment, sso:DeleteAccountAssignment, sso:ListPermissionSets, identitystore:ListUsers
  3. That's it — boto3 auto-discovers credentials from the instance metadata
Option B: STS AssumeRole Cross-account

PAM assumes an IAM role that has SSO Admin permissions.

The role's trust policy must trust PAM's current identity (instance profile, Roles Anywhere session, or IAM user).

Option C: IAM Roles Anywhere Best for On-Prem / OCI

For non-AWS environments (on-prem, OCI, GCP). Uses a certificate to authenticate.

Configure the certificate via .env: AWS_ROLES_ANYWHERE_CERT_PATH=/path/to/cert.pem
AWS_ROLES_ANYWHERE_KEY_PATH=/path/to/key.pem

Option D: IAM User Keys Dev Only

Simplest option for development. Uses long-lived IAM user access keys.

Not recommended for production. Use Instance Profile, AssumeRole, or Roles Anywhere instead.

Setup Guide

Follow these steps to configure AWS IAM Identity Center for this PAM application.

1 Choose an Authentication Method

Select the method that matches your deployment environment:

Environment Recommended Method Long-lived Secrets?
AWS EC2 / ECS / EKS Instance Profile No
Cross-account (any) STS AssumeRole No
On-prem / OCI / GCP Roles Anywhere No
Local development IAM User Keys Yes
2 Create an IAM Role for PAM

Create an IAM role with the following trust policy and permissions:

Trust Policy (for AssumeRole):
{{ '{' }}"Version": "2012-10-17","Statement": [{{ '{' }} "Effect": "Allow","Principal": {{ '{' }}"AWS": "arn:aws:iam::YOUR_ACCOUNT:role/PAM-Base-Role"{{ '}' }}, "Action": "sts:AssumeRole", "Condition": {{ '{' }}"StringEquals": {{ '{' }}"sts:ExternalId": "your-external-id"{{ '}' }}{{ '}' }} {{ '}' }}]{{ '}' }}
Permissions Policy:
{{ '{' }}"Version": "2012-10-17","Statement": [ {{ '{' }}"Effect": "Allow","Action": [ "sso:CreateAccountAssignment", "sso:DeleteAccountAssignment", "sso:ListPermissionSets", "sso:DescribePermissionSet", "sso:ListInstances", "identitystore:ListUsers", "identitystore:DescribeUser" ],"Resource": "*"{{ '}' }} ]{{ '}' }}
3 Configure IAM Roles Anywhere (if on-prem)

If running outside AWS, set up IAM Roles Anywhere:

  1. Create a trust anchor in IAM Roles Anywhere with your CA certificate
  2. Create a profile that maps to the IAM role above
  3. Install the aws_signing_helper or use the rolesanywhere-credential-helper
  4. Set the certificate and key paths in your .env file
# .env configuration for Roles Anywhere
AWS_ROLES_ANYWHERE_CERT_PATH=/etc/pam/cert.pem
AWS_ROLES_ANYWHERE_KEY_PATH=/etc/pam/key.pem
4 Add AWS Roles in PAM

After configuring AWS, add the permission sets you want to manage:

  1. Go to Django Admin → Roles → Privileged roles
  2. Click Add privileged role
  3. Set Provider to AWS
  4. Set Permission Set ARN to the ARN of the permission set
  5. Set AWS Account ID to the target account

Find permission sets via: aws sso-admin list-permission-sets --instance-arn

5 Test the Configuration

Once configured:

  1. Go to Roles page and verify permission sets are listed
  2. Create a test access request for an AWS role
  3. Approve the request and verify the account assignment is created
  4. Check the Audit Log for provisioning events
